# Деплой: домен, хостинг, база, почта

Это не «нажми кнопку», а последовательность с проверками после каждого шага.
Деньги начинают тратиться с шага 3, поэтому первые два шага бесплатны.

Бюджет проекта: до запуска 500–1500 ₽, дальше 0–1000 ₽/мес. Ниже — вариант,
который укладывается в эти рамки без кнопки «обновить тариф».

---

## 0. Что понадобится

- домен в зоне `.ru` — 200–400 ₽/год (reg.ru, timeweb, любой регистратор);
- аккаунт на Railway (или Render) — приложение;
- Postgres в облаке — Neon free (0,5 ГБ) хватает на первые сотни читателей;
- Resend free — 3000 писем в месяц, этого достаточно для подтверждения адресов
  и сброса пароля;
- репозиторий на GitHub — уже есть.

## 1. Домен (бесплатно, кроме самого домена)

1. Купи домен `knigomany.ru`.
2. Ничего пока не настраивай в DNS — сначала подними приложение, иначе получишь
   полдня «сайт не открывается», не понимая, что именно не работает.

Проверка: домен виден в панели регистратора, срок оплаты — год.

## 2. База данных (бесплатно)

1. Neon → New Project → регион ближе к хостингу (Frankfurt).
2. Скопируй строку подключения вида
   `postgres://user:pass@ep-xxx.eu-central-1.aws.neon.tech/knigomany?sslmode=require`.
3. Проверь её локально, до всякого хостинга:

```bash
DATABASE_URL='postgres://...' npm run db:migrate
DATABASE_URL='postgres://...' npm run db:status
```

Должно быть `[x]` напротив всех миграций. Если здесь ошибка — на хостинге будет
та же ошибка, только искать её дольше.

## 3. Приложение на Railway

1. New Project → Deploy from GitHub repo → выбери репозиторий.
2. Railway прочитает `railway.json`: сборка `npm ci --omit=dev`,
   запуск `npm run db:migrate && node src/server.js`, healthcheck `/healthz`.
3. Variables — заполни:

```env
NODE_ENV=production
PUBLIC_URL=https://knigomany.ru
SESSION_SECRET=<openssl rand -hex 32>
DATABASE_URL=<строка из Neon>
MAIL_FROM="Книгоманы <noreply@knigomany.ru>"
RESEND_API_KEY=<ключ Resend>
```

`PORT` задавать не нужно: Railway подставляет свой, приложение его читает.

4. Deploy. В логах должно быть `подключение к БД установлено` и `сервер запущен`,
   а не список ошибок окружения (если они есть — приложение специально не стартует,
   смотри `docs/ENVIRONMENT.md`).
5. Открой выданный Railway-адрес `*.up.railway.app` — сайт должен работать.

Проверка на этом шаге: `curl -I https://<railway-адрес>/healthz` → `200`.

## 4. Домен на хостинг и HTTPS

1. Railway → Settings → Networking → Custom Domain → `knigomany.ru`
   и `www.knigomany.ru`.
2. В DNS у регистратора: `A`/`CNAME` на то, что покажет Railway (обычно `CNAME`
   на `*.up.railway.app`). TTL поставь 300 на время настройки.
3. Подожди 5–30 минут, пока Railway выпустит сертификат.

Проверка:

```bash
curl -I http://knigomany.ru/          # 308 на https://knigomany.ru/
curl -I https://www.knigomany.ru/     # 308 на https://knigomany.ru/
curl -I https://knigomany.ru/healthz  # 200, без редиректа
```

Три адреса, один сайт. Редиректы делает `src/lib/https.js`, они включены только
при `NODE_ENV=production` — на localhost ничего не ломается.

## 5. Почта

1. Resend → Domains → Add domain `knigomany.ru`.
2. Пропиши в DNS записи, которые он покажет: `SPF` (TXT), `DKIM` (TXT/CNAME),
   `DMARC` (TXT `v=DMARC1; p=none;`). DMARC начни с `p=none` — не отправляй
   свои письма в спам из-за слишком строгой политики.
3. Дождись статуса Verified, создай API key, положи в `RESEND_API_KEY`,
   перезапусти приложение.

Проверка — по-настоящему, а не «должно работать»:

1. Зарегистрируй новый аккаунт на своём домене.
2. Письмо должно прийти в течение минуты, не в спам.
3. Нажми «Подтвердить адрес» — должно открыться `https://knigomany.ru/vhod`
   с сообщением об успехе.
4. Проверь «Забыли пароль» на свой адрес: ссылка должна вести на твой домен,
   новый пароль — работать.

Если письма нет: Resend → Logs покажет, принял ли он письмо. Если принял, а
письма нет — смотри DMARC и папку «спам».

## 6. Первый администратор

Демо-данные в продакшене не заливаются (`DB_SEED` работает только для PGlite).
Значит, первого админа нужно создать руками:

```bash
DATABASE_URL='postgres://...' ADMIN_EMAIL='you@knigomany.ru' \
  node -e "require('./src/db/seed').seedAdmin().then(r => console.log(r))"
```

Пароль сгенерируется сам и напечатается один раз. Хочешь свой — добавь
`ADMIN_PASSWORD`, но тогда он останется в истории команд. Сразу после входа смени пароль в
`/nastroyki`. Демо-читателей (`anna@example.com` и остальные) в продакшене быть
не должно — это чужие аккаунты с известным паролем.

## 7. Что проверить после деплоя

| Проверка | Как | Ожидание |
|---|---|---|
| Сайт открывается | браузер | главная, каталог, книга |
| HTTPS | замок в адресной строке | сертификат валидный |
| www и http | `curl -I` | 308 на канонический адрес |
| Регистрация | новый адрес | письмо пришло, вход работает |
| Сброс пароля | «Забыли пароль» | ссылка на свой домен |
| Картинка года | `/knizhnyy-god` | PNG скачивается |
| sitemap | `/sitemap.xml` | адреса на `https://knigomany.ru` |
| robots | `/robots.txt` | закрыты личные разделы |
| Ошибка 500 | `/net-takoy-stranitsy` | красивая 404, без стека |
| Здоровье | `/healthz` | `{"ok":true}` |

## 8. Откат, если что-то пошло не так

- Код: Railway → Deployments → предыдущий деплой → Redeploy.
- Миграции назад: `DATABASE_URL='...' npm run db:rollback` (по одной).
- Полный откат схемы до пустой базы: только с бэкапом. Бэкапы — этап 18,
  до него на проде не должно быть данных, которые жалко потерять.
- Домен отвязать не проблема: DNS указывает на Railway, а не наоборот.
