# Наполнение: как добавить книгу, подборку и автора

Каталог живёт в папке `content/` — обычные JSON-файлы, без базы и без деплоя кода.

```text
content/
├── books.json        # каталог: 345 книг
├── collections.json  # 20 подборок
└── authors.json      # 10 страниц авторов
```

## Зачем отдельно от сида

`src/db/seed.js` — это **демо для разработки**: пять читателей с известным
паролем, полки, рецензии, клубы. На проде таких аккаунтов быть не должно.

`content/` — это **каталог**: он одинаков и дома, и в продакшене. Поэтому
наполнение заливается отдельной командой:

```bash
npm run content:check           # только проверить файлы, ничего не писать
npm run content:load            # залить новое, не трогая существующее
npm run content:load -- --update  # обновить описания и годы у существующих книг
```

Для локальной разработки с PGlite добавь `DB_DRIVER=pglite`.

## Как добавить книгу

Открой `content/books.json` и добавь объект:

```json
{
  "title": "Пикник на обочине",
  "author": "Аркадий и Борис Стругацкие",
  "year": 1972,
  "pages": 256,
  "genre": "Фантастика",
  "description": "Зона, куда лучше не ходить, и люди, которые всё равно идут — за деньгами, за смыслом, за чудом, которое не просили."
}
```

Правила:

| Поле | Обязательно | Ограничения |
|---|---|---|
| `title` | да | от 2 символов, уникален вместе с автором |
| `author` | да | как на обложке, «Имя Фамилия» |
| `description` | да | 80–1200 символов, **своими словами** |
| `genre` | нет | должен быть в списке жанров |
| `year` | нет | 1000 — текущий год + 2, иначе `null` |
| `pages` | нет | 10–20000 |

Адрес страницы (`slug`) не пишется руками: он собирается из автора и названия
так же, как в `src/lib/slug.js`. Поэтому «Мастер и Маргарита» Булгакова всегда
будет на `/knigi/mihail-bulgakov-master-i-margarita`.

После правки:

```bash
npm run content:check
```

Если есть ошибки — загрузка не начнётся. Это специально: половина каталога
хуже, чем никакого.

## Про описания: что можно и что нельзя

**Нельзя:** пересказывать сюжет целиком, копировать аннотации издательств,
вставлять отрывки текста. Это чужая работа и, если пересказ длинный, чужие
права (ст. 1301 ГК).

**Можно:** рассказать своими словами, о чём книга, кому она подойдёт и что
с ней происходит у читателя. 80–600 символов обычно достаточно.

Плохо: «Роман рассказывает о судьбе... В центре повествования...»
Хорошо: «Человек получает власть над временем и обнаруживает, что
распорядиться ею некуда».

Цитаты — только короткие, до 300 знаков, с указанием автора.

## Как добавить подборку

```json
{
  "slug": "chto-podarit-chitatelyu",
  "title": "Что подарить читателю",
  "description": "Десять книг, которые не стыдно подарить: с хорошей полиграфией и без сюрпризов в содержании.",
  "books": [
    "anton-chehov-dama-s-sobachkoy",
    "mihail-bulgakov-master-i-margarita"
  ]
}
```

- в `books` — **адреса книг** из `books.json`, а не названия;
- минимум 3 книги, максимум 20 (больше никто не пролистает);
- порядок в массиве = порядок на странице;
- если хотя бы одного адреса нет в каталоге, загрузка откажется целиком.

Список адресов можно получить так:

```bash
node -e "require('./content/books.json').forEach(b => console.log(b.title, '→', require('./src/lib/slug').slugify(b.author + ' ' + b.title)))"
```

## Как добавить автора

```json
{
  "name": "Михаил Булгаков",
  "years": "1891–1940",
  "bio": "Врач по образованию, писатель по призванию. Главный роман писал восемь лет и не увидел напечатанным."
}
```

Страница автора показывает книги из каталога по точному совпадению поля
`author`, поэтому имя должно совпадать с тем, что в `books.json`, буква в букву.

Биография — до 1500 символов, без энциклопедического тона: читателю важно
понять, брать ли следующую книгу этого человека.

## Что происходит при загрузке

1. Все три файла проверяются целиком (`src/lib/content.js`).
2. Жанры создаются по названию, если их ещё нет.
3. Книги создаются, если такого адреса нет. Существующие не перетираются —
   правки, сделанные в админке, остаются.
4. С `--update` обновляются только `title`, `author`, `description`, `year`,
   `pages`. Обложки и счётчики не трогаются.
5. Подборки и авторы обновляются всегда: это редакционный контент, его
   правят в файлах.

## Проверки, которые не дают испортить каталог

- пустое или слишком короткое описание;
- неизвестный жанр;
- год издания из будущего или из XII века (для древних текстов `year: null`);
- две книги с одинаковым адресом;
- подборка из несуществующих книг или из двух книг;
- автор без имени.

Всё это ловится до записи в базу: `npm run content:check` в CI и в тестах.

## Как добавить статью в «Журнал»

Статьи лежат в `content/articles.json` — отдельно от каталога: их правит
редактор, а не загрузчик книг, и деплой для новой статьи не нужен (файл
читается при старте приложения). Формат:

```json
{
  "slug": "kak-vesti-dnevnik-chteniya",
  "title": "Как вести дневник чтения, чтобы не бросить через месяц",
  "description": "Одно предложение: что человек узнает из статьи. До 200 знаков.",
  "topic": "Практика",
  "readingMinutes": 5,
  "datePublished": "2026-01-12",
  "sections": [
    { "heading": "Заголовок секции", "paragraphs": ["Абзац.", "Ещё абзац."] }
  ]
}
```

Правила, которые проверяет валидатор (`src/lib/articles.js`):

| Поле | Ограничение | Почему |
|---|---|---|
| `slug` | латиница, 5–80 знаков, уникален | адрес `/zhurnal/<slug>`, ключ для «читайте также» |
| `title` | 10–120 знаков | влезает в `<title>` и в карточку списка |
| `description` | 40–200 знаков | это сниппет в поисковой выдаче |
| `topic` | `Практика`, `Подборки`, `Клубы` | темы — навигация по разделу |
| `sections` | 2–12 секций, в каждой заголовок и абзацы | статья из одного абзаца — не статья |
| абзац | 40–1500 знаков | длиннее — стена текста |
| текст | 200–2500 слов | короче — «тонкий текст», длиннее — уже глава |

Статья с ошибкой **не публикуется**: она отбрасывается при загрузке и
попадает в `journal.errors`. Раздел при этом работает — лучше показать
31 статью из 32, чем половину текста.

Проверка: `node --test tests/integration/journal.test.js`. Тест читает
реальные статьи из `content/`, поэтому битый файл не доедет до продакшена.

Правила по содержанию: не пересказывать сюжеты книг, не давать ссылок на
пиратские копии, цитаты — не длиннее 300–500 знаков с указанием автора.
Ссылка в конце статьи ведёт на полку или подборку, а не в магазин.

## Как завести стартовые клубы

Клубы лежат в `content/clubs.json`. Это не демо-данные: три клуба с
расписанием нужны, чтобы раздел `/kluby` на старте не выглядел пустым.

```json
{
  "slug": "klassika-po-sredam",
  "name": "Классика по средам",
  "description": "Зачем идти в клуб: 40–1000 знаков.",
  "ownerEmail": "anna@example.com",
  "isPrivate": false,
  "currentBookSlug": "arkadiy-i-boris-strugackie-piknik-na-obochine",
  "schedule": [
    { "chapter": 1, "inDays": 3, "note": "О чём говорим на встрече" }
  ]
}
```

- `ownerEmail` — ведущий, а не id: id на проде и на демо разные. **Человек
  должен существовать заранее** — клуб без ведущего не создаётся (в лог
  попадёт «клубы без ведущего»);
- `inDays` — через сколько дней встреча от сегодняшнего дня: фиксировать
  даты в файле бессмысленно, при загрузке через месяц они станут прошлым;
- `currentBookSlug` — книга из каталога. Если книги нет, загрузка скажет
  об этом и не станет создавать клуб с битой ссылкой;
- повторный запуск не создаёт второй клуб и не перетирает правки: клуб
  живёт своей жизнью, люди меняют название и текущую книгу.

Загрузка: `npm run content:load` (нужна миграция 005 и аккаунты ведущих).

## Что осталось руками

- посты в соцсетях (этап 19.4, «за владельцем»): тексты статей готовы и
  лежат в «Журнале», а сами публикации в Telegram/VK/Дзене — руками;
- обложки: сейчас типографические заглушки, загрузка файлов — после беты;
- ведущие стартовых клубов: клубы грузятся из файла, но аккаунты ведущих
  (`ownerEmail`) нужно создать заранее — на проде это приглашённые люди.
