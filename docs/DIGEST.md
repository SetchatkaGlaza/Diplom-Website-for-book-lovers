# Дайджест и возврат ушедших

Письма на почту: одно письмо в неделю и «вас давно не было». Раздел этапа 22.4.

## Зачем это вообще

Люди не возвращаются не потому, что им не понравилось, а потому, что забыли.
Письмо раз в неделю — самый дешёвый способ напомнить о себе: оно не требует
ни рекламы, ни новых функций. Но именно письма чаще всего превращают хороший
сайт в спам, поэтому в правилах больше ограничений, чем возможностей.

## Кому пишем

Только тем, у кого выполнены **все** условия:

| Условие | Где | Почему |
|---|---|---|
| Галочка «присылать недельный дайджест» | `/nastroyki` | по умолчанию **выключена**: согласие — действие, а не молчание |
| Адрес подтверждён | письмо после регистрации | писать на неподтверждённый адрес — значит писать в пустоту |
| Аккаунт не удалён и не заблокирован | `users.deleted_at`, `users.is_blocked` | |
| Нет отметки об отписке | `email_unsubscribes` | отписка сильнее галочки |

Для «вас давно не было» дополнительно: человек молчал **дольше 21 дня**
и такое письмо ему не уходило в последние **21 день**.

## Что в письме

Недельное письмо: что дочитано за неделю (до трёх книг), что читается
сейчас, сколько осталось до годовой цели и одна кнопка «Открыть полку».
Если закрытых книг нет — так и написано: «это нормально, иногда неделя
уходит на одну главу». Письмо не должно создавать чувство долга.

Письмо «вас давно не было»: полка на месте, ничего восстанавливать не нужно,
вот книги, которые открыты. Никаких «мы скучали» и скидок.

Правила текста: без вины, без «вы ничего не прочитали», без обещаний,
одна ссылка на продукт и одна — на отписку.

## Как запускается

Рассылка **не** висит на таймере внутри приложения: на проде может быть
несколько инстансов, и два таймера отправят два письма. Запуск — отдельная
команда или кнопка в админке.

```bash
npm run digest:dry                  # пробный прогон: собрать письма, ничего не отправляя
npm run digest                      # отправить недельное письмо
npm run digest:stats                # что ушло и что сломалось за 30 дней

node src/db/digest-cli.js run --kind comeback
node src/db/digest-cli.js run --limit 10
node src/db/digest-cli.js recipients    # кому можно писать (до 1000, первые 20 в выводе)
```

Cron на сервере (понедельник, 10:00):

```cron
0 10 * * 1 cd /app && node src/db/digest-cli.js run >> logs/digest.log 2>&1
```

Railway: **Settings → Cron Jobs** → `node src/db/digest-cli.js run`, расписание
`0 10 * * 1`.

Из админки: `/admin/rassylka` — счётчики, журнал писем, запуск с галочкой
«пробный прогон» (по умолчанию включена — так безопаснее).

## Почему повторный запуск безопасен

Период письма (начало недели, понедельник UTC) записывается в таблицу
`digests` с уникальным индексом `(user_id, kind, period_start)`. Второй
запуск в ту же неделю видит запись и пропускает человека. Для «вас давно
не было» дополнительно проверяется дата последнего такого письма.

Ошибка отправки одному адресу не останавливает рассылку: запись получает
статус `failed` и текст ошибки, остальные письма уходят.

## Отписка

В каждом письме есть ссылка `/otpiska?e=<sha256 адреса>`. В ссылке нет
ни id, ни самого адреса: по ней нельзя перебрать чужие ящики, а отписаться
можно без входа в аккаунт (человек пришёл из письма и пароль не помнит).

Отписка делает две вещи: ставит отметку в `email_unsubscribes` и снимает
галочку `notify_digest` в аккаунте — иначе в настройках было бы «присылать»,
а писем бы не было.

Включить письма обратно можно в `/nastroyki`: это удаляет отметку об отписке.
Так работает требование «отписаться легко, вернуться осознанно».

## Что проверить перед запуском рассылки

1. `npm run digest:dry` — прочитать три первых письма глазами. Если в них
   есть «вы давно не читали» или стыд — переписать.
2. `npm run digest:stats` — убедиться, что в прошлый раз не было пачки
   `failed` (обычно это отвалившийся SMTP или неверный `MAIL_FROM`).
3. Проверить, что `RESEND_API_KEY` или `SMTP_HOST` заданы: без них письма
   пишутся в лог, а команда предупреждает об этом.
4. Отправить себе: включить галочку в своих настройках, запустить
   `node src/db/digest-cli.js run --limit 1`, посмотреть письмо в почте
   и нажать «Отписаться» — это единственная честная проверка ссылки.

## Ограничения, записанные честно

- **Домен и почтовый сервис** настраиваются только владельцем: без
  верификации домена в Resend письма уходят в спам или не уходят вовсе.
  Инструкция — `docs/OPERATIONS.md`.
- **Открытия писем не отслеживаются**: поле `opened_at` есть, но пиксель
  не ставим — это лишний трекер в письме, а пользы на 3000 пользователях мало.
- **Отписка перебирает пользователей в памяти** (до 10 000) при каждом
  клике: на старте это быстрее, чем возиться с поиском по хешу в SQL.
  Когда пользователей станет больше, нужен индекс по `sha256(email)`.
- **Скорость отправки** ограничена 50 письмами за прогон по умолчанию:
  Resend и SMTP не любят всплесков, а большие батчи упираются в лимиты тарифа.
- **Возврат ушедших — это не «реактивация»**: если человек не вернулся
  после двух писем, третье не отправляем. Настойчивость в письмах стоит
  дороже, чем потерянный читатель.
